# Decisions

Locked 2026-08-23 by the architect. Each entry was a spec ambiguity; each is now a rule.
To reverse one, edit this file, then the affected clauses in `docs/spec/mastery-rules.md`,
then the fixtures named after those clauses. Never reverse one in code alone.

Two engine-contract changes follow from D2 and D5, and supersede the original draft in
`architecture.md` §1:

- **Novelty is derived, not declared.** The `novelSurface` flag is removed from the event.
  The engine decides from `seenSurfaces` and `novelFailures` whether the U2 exemption
  applies, so a caller cannot claim an exemption it has not earned (MR-1.2).
- **The engine owns echo rounds.** There is no `echo_result` event. `openEcho` accumulates
  per-lamp results and the engine decides when a round closed and whether it passed, so the
  UI cannot report an outcome the answers do not support (MR-1.3, MR-6.1–6.2).

Both changes move authority from the caller to the pure function. That is the direction
authority should always move in this codebase.

| **D27** | *Decided 2026-08-29, launch deadline.* The guest→account merge rule `build-plan.md`'s M7 entry deferred defining: per character, the **higher status wins**; on a **tie, the earlier `almostAt` is kept** so an echo clock already running is never reset. | **D28** | *Decided 2026-08-30, launch deadline.* Better Auth's default session `expiresIn` (7 days) exactly matches the second echo's 168h interval: a family that registers, rides once, and — as the return-ticket design itself intends — does not open the app again until day eight would find the session cookie already expired at the moment the product's central promise comes due, independent of any browser's storage-eviction behaviour (the cookie's own Max-Age does it alone; the cookie was already confirmed `HttpOnly`, so this is not the same failure as Safari's script-writable-storage purge, just an equally fatal one). Session lifetime is extended: `expiresIn: 90d`, `updateAge: 1d` (rolling refresh on any use). **Not a change of auth method** — same server-set `HttpOnly; Secure; SameSite=Lax` cookie, confirmed by direct `Set-Cookie` inspection before and after. **Follow-up, not done here:** a 90-day session on a shared family device is a wider window for whoever holds the device to reach the parent surface; the right mitigation is step-up re-auth on sensitive actions (email change, account deletion, future billing), not a shorter global session. **This decision covers registered sessions only — guest progress in `localStorage` remains fully subject to Safari's ITP purge regardless**, since that storage is script-writable and no cookie config touches it. The two cases must not be conflated: `child-home-and-sessions.md` §5's save prompt and 「じぶんの えきを つくる」 are what protect a guest family, not this fix. | `apps/web/src/lib/auth/server.ts` |

| **D29** | *Decided 2026-08-31, launch deadline.* R1 (`docs/reviews/remediation-plan.md`) made `BETTER_AUTH_SECRET` and `DATABASE_URL` crash the process at startup when unset in production, but deliberately left `BETTER_AUTH_URL` and the `GROK_AUTH_CLIENT_ID`/`GROK_AUTH_CLIENT_SECRET` pair as **soft fallbacks** — not because they're safe, but because hard-requiring them from a sandbox with no GCP access means guessing at the live Cloud Run service URL and at OAuth credentials that were never provisioned. A wrong `BETTER_AUTH_URL` breaks every credentialed auth request (`Invalid origin`) just as thoroughly as a missing secret does; it is not lower-severity, only lower-certainty from where the fix was written. **This is a launch-week task, not a backlog item:** someone with GCP access must confirm the deployed service's real URL (and the `--tag welcome-polish` preview URL's relationship to it) before `BETTER_AUTH_URL` can be safely hard-required, and confirm whether federated OAuth is actually being wired up for launch before the GROK pair is. Until then, both remain silently permissive in production — a known, recorded gap, not a discovered one. | R1, `docs/reviews/remediation-plan.md`, `apps/web/src/lib/auth/server.ts` |

Subtle text `#8a8478` → `#787368` (24%, taken deliberately despite being visible — いみ/訓読み/音読み/grade-and-stroke labels are read by six-year-olds on phones in bright rooms; "3.59 isn't a compliance number, it's a legibility number," and the design intent was restraint, not faintness).
